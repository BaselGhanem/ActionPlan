# دار الدواء — خطة الأنشطة الطبية 2027

واجهة عربية متجاوبة بهوية دار الدواء، Firebase Authentication وFirestore مباشرة، وتعمل على Spark دون Cloud Functions أو خادم خارجي. الواجهة منشورة عبر GitHub Pages.

## التفعيل

افتح [صفحة التهيئة](https://baselghanem.github.io/ActionPlan/setup.html) واتبع خطوات نشر القواعد وإنشاء المسؤول الأول. لا يحتاج المستودع مفتاح خدمة أو كلمة مرور. لا تكفي إعدادات firebaseConfig وحدها لمنح صلاحيات الوصول.

1. فعّل Email/Password في Authentication وأضف baselghanem.github.io إلى Authorized domains.
2. انشر محتوى firestore.rules في Firestore > Rules.
3. أنشئ حساب Authentication بالبريد admin@users.dadactionplan.app وكلمة مرور تختارها.
4. أنشئ مستند setup/bootstrap في Firestore وفيه adminUid من نوع string بقيمة UID للحساب السابق.
5. ادخل باسم admin وكلمة مرورك. ينشئ النظام ملف المسؤول والتهيئة تلقائيا. أضف الفرق والميزانيات السنوية ثم القوائم والحسابات.

## العمليات

- جميع الفرق ترى العملاء والأنشطة ومبالغها؛ منشئ النشاط وAdmin وMarketing Manager يعدلون النشاط.
- Admin وحده ينشئ الحسابات ويرفع قوائم العملاء. المدير يدير الميزانيات والأنشطة وأنواعها والتقارير.
- قوالب Excel XLSX مستقلة لكل فريق: نزّل قالبا فارغا أو قائمة الفريق الحالية داخل القالب، ثم ارفع القالب الخاص بالفريق نفسه مع معاينة وتحقق من الأخطاء قبل الاستبدال. يقبل النظام 6 أعمدة ثابتة؛ الكود والاسم إلزاميان، والنوع والتخصص والمنطقة والتصنيف اختيارية. الكود نص للحفاظ على الأصفار الأولى، ولا يسمح بالرمز / أو بالأكواد المكررة؛ لا يقبل CSV أو اللصق الحر في شاشة الرفع.
- الكود يوحد العميل، آخر ملف يعتمد البيانات الأساسية، والتصنيف مستقل لكل فريق. الاستبدال يحفظ تاريخ الأنشطة ويمنع مشاركات جديدة للفرق المحذوفة من العميل. رفع غير مكتمل يوقف مشاركة الفريق مؤقتا؛ إعادة رفع قائمة كاملة تعيد تفعيله.
- إجمالي النشاط يطابق حصص العملاء اليدوية، وحصة كل عميل توزع بالتساوي افتراضيا مع التعديل قبل الحفظ.
- المخطط يحجز الميزانية، والفعلي قابل للتحديث ويحل محل المخطط عند التنفيذ. تمنع المعاملات الذرية تجاوز الميزانية حتى مع طلبات متزامنة.
- إلغاء نشاط له فعلي للإدارة مع الاحتفاظ بالمصروف. حذف المخطط دون فعلي يعيد الحجز ويحتفظ بأثر التدقيق.
- التقارير تدعم الفرق والعملاء والشهر والنشاط والمنطقة والتخصص والتصنيف، وتصدير Excel بخمس أوراق منسقة.

## الحسابات

حساب واحد للفريق، باسم مستخدم وكلمة مرور. إنشاء الحساب من جلسة Firebase Auth ثانوية لا يخرج المسؤول. إعادة تعيين كلمة المرور تنشئ هوية Auth بديلة وتعطل ملف الهوية القديمة؛ يبقى accountId ثابتا لحفظ ملكية الأنشطة. لا تخزن كلمات المرور في Firestore. لإعادة تعيين كلمة مرور المسؤول نفسه استخدم Firebase Console. الهوية القديمة تبقى في Authentication ويمكن للمسؤول حذفها من Console، لكنها ممنوعة من بيانات التطبيق.

## التنفيذ والتحقق

```bash
npm ci
npm test
npm run test:firebase
npm run build
npm run test:sites
```

اختبارات Firebase تستخدم مشروعا محليا تجريبيا ومحاكيات Authentication وFirestore. لا تكتب على المشروع الحقيقي. نشر القواعد الحقيقي خطوة منفصلة من Console.

الأموال سنتات صحيحة. تعتمد القواعد وثائق تحقق غير قابلة للتعديل ثم معاملة واحدة للنشاط والميزانيات وسجل التدقيق. حتى 8 عملاء و8 فرق متأثرة لكل نشاط (بما فيها الفرق السابقة عند التعديل)، وهو حد معلن لتوافق حدود Firestore Security Rules. السنوات: 2027 حاليا.

Spark لها حصص مجانية محدودة للقراءة والكتابة والتخزين؛ التطبيق لا يفعل فوترة، وقد يتوقف عند استنفاد الحصة. التحقق متعدد الخطوات يزيد عدد العمليات لكل حفظ. يجلب التحميل الحالي قوائم السنة كاملة؛ الأحجام الكبيرة تحتاج ترقيم صفحات وتخطيطا لحصص الاستخدام. سجلات التدقيق والتحقق تحتفظ بتاريخها وتستهلك تخزينا. العرض التجريبي ?demo=1 يعمل في الذاكرة ولا يحفظ Firebase.
